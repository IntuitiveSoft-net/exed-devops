# LAB : AWS MCP Server (Bonus)

**Objectives**

- understand how an MCP server can accelerate AWS automation workflows
- configure AWS API MCP Server with your lab AWS credentials
- create a VPC stack (VPC, subnets, internet gateway, route table) using natural language
- validate and clean up resources with AWS CLI

## Insight 1. MCP for IaC automation

Model Context Protocol (MCP) connects an AI assistant to external tools. In this lab, the tool is the AWS API MCP Server, which executes validated AWS CLI operations through your AWS credentials.

This is useful for IaC training because it combines:

- AWS API/CLI skills from `22.aws-cli.md`
- network concepts from `20.aws-overview.md` and `21.aws-console.md`
- automation mindset from Terraform and Ansible labs

As of April 2026, AWS Labs recommends `awslabs.aws-api-mcp-server` as the general-purpose starting point for AWS MCP workflows.

## Task 2. Prerequisites

You should already have:

- AWS CLI installed
- SSO or AWS credentials configured (default profile)
- access to region `us-east-1`

Run:

```bash
aws --version
aws sts get-caller-identity
aws configure list
```

Expected output (example):

```console
aws-cli/2.x.x ...
{
  "UserId": "...",
  "Account": "708113109960",
  "Arn": "arn:aws:sts::708113109960:assumed-role/..."
}
```

## Task 3. Install uv runtime

Install `uv` (used to run the MCP server package):

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Load your shell environment and verify:

```bash
source "$HOME/.local/bin/env"
uv --version
uv python install 3.10
```

## Task 4. Configure AWS API MCP server

In your lab project root, create a `.mcp.json` file:

```json
{
  "mcpServers": {
    "awslabs.aws-api-mcp-server": {
      "command": "uvx",
      "args": [
        "awslabs.aws-api-mcp-server@latest"
      ],
      "env": {
        "AWS_REGION": "us-east-1",
        "AWS_API_MCP_PROFILE_NAME": "default",
        "REQUIRE_MUTATION_CONSENT": "true"
      },
      "disabled": false,
      "autoApprove": []
    }
  }
}
```

Then restart your MCP client (Cursor, VS Code MCP, Claude Code, etc.) so the new server is loaded.

## Task 5. Validate MCP read access

In your AI assistant chat, issue the following request:

```text
Using awslabs.aws-api-mcp-server, run read-only checks:
1) aws sts get-caller-identity
2) aws ec2 describe-vpcs --region us-east-1
Return a short summary of account ID and number of VPCs.
```

You should receive:

- your account identity
- existing VPC inventory
- no mutation prompt (read-only actions)

## Insight 6. Safe mutation guardrails

Before creating resources:

- use dedicated tags for cleanup (`ManagedBy=aws-mcp-lab`, `Owner=podX`)
- ask the assistant to show planned CLI commands before execution
- keep `REQUIRE_MUTATION_CONSENT=true` enabled
- avoid production credentials for this type of exploratory workflow

## Task 7. Create a VPC with MCP

Use this prompt in your AI assistant:

```text
Using awslabs.aws-api-mcp-server in us-east-1, create this network stack and tag every resource with ManagedBy=aws-mcp-lab and Owner=podX:
- VPC CIDR 10.42.0.0/16, Name=podX-mcp-vpc
- Public subnet CIDR 10.42.1.0/24, Name=podX-mcp-public-subnet
- Private subnet CIDR 10.42.2.0/24, Name=podX-mcp-private-subnet
- Internet Gateway Name=podX-mcp-igw attached to the VPC
- Route table Name=podX-mcp-public-rt with route 0.0.0.0/0 to the IGW
- Associate that route table with the public subnet

Important:
1) First show the AWS CLI commands you plan to execute
2) Ask for confirmation before mutation commands
3) Return final IDs in JSON (VpcId, PublicSubnetId, PrivateSubnetId, InternetGatewayId, RouteTableId, RouteTableAssociationId)
```

Expected result (example):

```json
{
  "VpcId": "vpc-0abc1234def567890",
  "PublicSubnetId": "subnet-0123abcd4567ef890",
  "PrivateSubnetId": "subnet-0456abcd7890ef123",
  "InternetGatewayId": "igw-0123456789abcdef0",
  "RouteTableId": "rtb-0123456789abcdef0",
  "RouteTableAssociationId": "rtbassoc-0123456789abcdef0"
}
```

## Task 8. Validate resources with AWS CLI

Verify your VPC:

```bash
aws ec2 describe-vpcs \
  --region us-east-1 \
  --filters Name=tag:ManagedBy,Values=aws-mcp-lab Name=tag:Owner,Values=podX \
  --query 'Vpcs[*].{VpcId:VpcId,Cidr:CidrBlock,Name:Tags[?Key==`Name`]|[0].Value}' \
  --output table
```

Verify subnets:

```bash
aws ec2 describe-subnets \
  --region us-east-1 \
  --filters Name=tag:ManagedBy,Values=aws-mcp-lab Name=tag:Owner,Values=podX \
  --query 'Subnets[*].{SubnetId:SubnetId,Cidr:CidrBlock,Az:AvailabilityZone,Name:Tags[?Key==`Name`]|[0].Value}' \
  --output table
```

Verify route table and default route:

```bash
aws ec2 describe-route-tables \
  --region us-east-1 \
  --filters Name=tag:ManagedBy,Values=aws-mcp-lab Name=tag:Owner,Values=podX \
  --query 'RouteTables[*].{RouteTableId:RouteTableId,Routes:Routes[*].DestinationCidrBlock,Name:Tags[?Key==`Name`]|[0].Value}' \
  --output table
```

## Task 10. Clean up resources

Use this prompt:

```text
Using awslabs.aws-api-mcp-server, delete all resources tagged ManagedBy=aws-mcp-lab and Owner=podX in the correct AWS dependency order.
Show delete commands before execution, ask for confirmation, then return deleted resource IDs.
```

Validate cleanup:

```bash
aws ec2 describe-vpcs \
  --region us-east-1 \
  --filters Name=tag:ManagedBy,Values=aws-mcp-lab Name=tag:Owner,Values=podX \
  --query 'Vpcs[*].VpcId'
```

Expected output:

```json
[]
```
